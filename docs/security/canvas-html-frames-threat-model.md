# Canvas HTML frames threat model

- Date: 2026-10-13
- Threat model id: `canvas-html-frames-v1`
- Status: Accepted with
  [Canvas documents, designs, and prototypes](../architecture.md#canvas-documents-designs-and-prototypes).
  Static frames that run nothing ship today under
  [0164](../decisions/0164-canvas-designs-are-html-in-a-frame-that-runs-nothing.md),
  measured and themed static frames (F2) ship with Canvas schema version 16,
  asset-bearing static frames (F5) with version 17, and running frames with
  version 18, with F1, F3, F4, F6, F7, F8, F9, and F10 implemented and tested.
- Scope: agent-authored HTML, CSS, and script drawn in a Canvas `design`
  frame, in the sidebar, the thread, preview, authenticated snapshots, and
  HTML export

## What the frame can hold

A frame holds what its author wrote, plus assets the server resolved for it
under the thread's authority. The author is the agent working for this
person, which already has that content and its own tools. The boundary
therefore protects Octant and the person from the frame, not the frame's own
content from its author: a frame must gain nothing the agent did not already
have, must not reach anything beyond its own bytes, and must not cost the
person their app.

## Assets

- Octant renderer origin: cookies, storage, DOM, RPC, preload, host tokens
- Project files and artifacts beyond the assets a frame names
- Loopback services and the network from the person's machine
- Renderer responsiveness (hang, memory, GPU)
- The person's trust in what is Octant chrome and what is a frame
- Snapshot viewers and export recipients

## Explicit non-goals

- Typed catalog blocks, including `tabs`, `columns`, diagram styles, Gantt,
  and Mermaid import; they render first-party components and no markup
- Public or anonymous share links
- A frame that runs script with `allow-same-origin`; no tier admits it
- Protecting frame content from the agent that wrote it

## Frame tiers

| Tier                        | Document                                          | Sandbox                                                                                                                                              | Policy                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Static (0164)               | `srcdoc`                                          | empty                                                                                                                                                | Frame policy below, narrowing the inherited app policy                                                                                                                                                             |
| Static, measured and themed | `srcdoc`                                          | `allow-same-origin` only                                                                                                                             | Same; no script can run, so same origin grants the page nothing it can use                                                                                                                                         |
| Running                     | Served by the host route with a single-use ticket | `allow-scripts` only, in the response's `sandbox` directive, and in the parent frame in a browser; on desktop a surface of its own with no route out | `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; connect-src 'none'; frame-src 'none'; form-action 'none'; base-uri 'none'` |

The static frame policy is today's: `default-src 'none'; style-src
'unsafe-inline'; img-src data:; font-src data:; base-uri 'none';
form-action 'none'`. The app policy's `frame-src` admits `'self'` and the
loopback design-page path (the packaged `file://` and Vite renderers reach the
loopback host); the remote gateway's document policy narrows a remote
client's `frame-src` to that path on its own origin.

| F3  | Frame sends data out                                            | Implemented, by client. `connect-src 'none'`, `img-src data: blob:`, `frame-src 'none'`, and `form-action 'none'`; declared images are written in as `data:` images by the host. A page policy does not cover WebRTC, and the renderer's `disable_non_proxied_udp` closes UDP only: on Electron 43.1.0 a sandboxed frame of the app window opened one TCP connection to a local TURN stand-in with the policy set (four STUN datagrams without it). **Desktop** therefore draws a running prototype in a `<webview>` in a session of its own whose proxy is a SOCKS address that is never a proxy, loopback included (`<-loopback>`), with `disable_non_proxied_udp`. The main process serves the one page to that session under a private scheme by asking the host itself, so the guest needs no route to the host's address; reads back before it is ready that a public and a loopback address both resolve to the dead proxy; and attaches the surface only for a ticketed design page on this host, replacing the element's partition, preload, and preferences. The session shares no cookies, storage, or permissions with the app and refuses permissions, devices, screen capture, downloads, new windows, and every navigation after the first. If the surface cannot be made the prototype does not run; it is never drawn in a frame, and the app window cancels any frame navigation to the design page. Evidence: `bun run smoke:canvas-prototype-containment` starts a hostile prototype in the shipped Electron and counts what reaches listeners on this machine. On 2026-10-13, in the control (a sandboxed frame with today's policy) 1 TCP connection arrived, from the TURN server named over TCP; in the contained surface 0 UDP datagrams, 0 TCP connections, 0 HTTP requests (fetch, XHR, an image, `sendBeacon`, an event source, a WebSocket upgrade, a form post, a popup, a self-navigation), and 0 requests to host routes arrived, both with the design page's policy and with that policy removed so only the session stood between the page and the network. The probe also asserts that a `<webview>` naming a beacon address, another host route, or a public site is not attached, that the surface's session is not the app's, and that the reserved shortcut reaches the window and not the page. **Not closed on desktop:** a host name the page asks the resolver for. A `dns-prefetch` link made the app's resolver look up a name of the page's choosing through the dead proxy (read from the network log), and Electron 43 has no per-session resolver rule; the same probe saw no lookup for a TURN server name in the contained surface, but a lookup of such a name did appear under a DNS-over-HTTPS resolver in an earlier trial, so this is treated as open. A name can carry a little data to a nameserver its author controls. The notice under a desktop prototype says so. **Remote browsers and exported files** are not contained against WebRTC (see Residual risk), bounded by what the frame holds: its author's content and named assets. The smoke's fetch, XHR, WebSocket, image beacon, and form submit reach nothing in a browser. |
| F4  | Ticket or session credential leaks to the frame                 | Implemented. The frame URL carries a single-use ticket (32 random bytes, held in memory, 10 seconds) issued by `POST /api/canvas/design-run` after the Canvas read check; it authorizes one version, design, and start frame, never a session token. The page route serves only a frame load, and every response, page or refusal, sends `Referrer-Policy: no-referrer` and `Cache-Control: no-store`. Route tests refuse a replayed, expired, guessed, or over-specified ticket, and a static design, another version, an unknown window, or another Project or mode. | F5  | Asset reference reaches beyond authority                        | Implemented. The server resolves only asset ids the definition declares, under the Canvas version's mode, Project, and thread, on every read through the authorized Canvas read (no cache). A Chat Project reaches only images generated in its own threads, never a path. Work and Code files go through the Work confinement sequence: no traversal, no symlink out of the root, one identity-checked handle. Only sniffed PNG, JPEG, GIF, or WebP within 3 MiB per image and 5 MiB per design. The renderer inlines the bytes as `data:` images; the markup policy admits only literal references to declared ids, so a frame cannot request an asset at run time. Unknown, refused, oversize, or non-image ids draw a placeholder and a `design-asset-unavailable` preview warning; the definition and journal hold references, never bytes. | F6  | Running frame hangs or exhausts the renderer                    | Implemented. Electron 43 runs sandboxed frames out of process by default (probed for same-site, cross-site, and `file://` parents; the parent kept running through the frame's infinite loop), and desktop enables `IsolateSandboxedIframes` with per-document grouping explicitly, because the default per-site grouping put the next prototype into a looping page's process, where it never loaded. A desktop prototype is a `<webview>` guest, a process of its own that is closed when the prototype is removed. The bridge sends a heartbeat every second; a frame that misses 5 seconds of it (10 for the first) while the window is visible is removed and shown as stopped, with Run again, and so is a frame that posts more than 250 messages in a second to the renderer. The thread starts a running frame only on Run. | F7  | Frame navigates the app, opens windows, or navigates itself out | Implemented. No `allow-top-navigation`, `allow-popups`, `allow-forms`, or `allow-modals`; the browser smoke's top navigation and `window.open` are refused. Static frames keep fragment-only links. Desktop cancels every navigation and redirect of a running prototype's surface after its first load (Electron `will-navigate`, `will-redirect`, and `will-frame-navigate` on the guest), and the session has no route to any page it could be sent to; the probe's `location = ...` after half a second reached no listener. An earlier Electron probe of the frame case cancelled `location = 'https://example.com/?x'`, a `meta` refresh, and a navigation after `pushState`. A remote browser cannot cancel it: there the navigated page can make any request a web page in that browser can, before and after it loads (the smoke's beacon saw it). Every client removes a frame on its second load, which limits how long such a page stays on screen, not what it sends. This remote exposure is accepted, bounded by what the frame holds; the Run control in a remote browser says the prototype is not network-contained there. ## Residual risk

- WebRTC is outside a page's content policy. Desktop contains it by giving a
  running prototype a session with no route out (F3); a remote browser and an
  exported file do not, and there a peer connection that names a TURN server
  over TCP connects (on Electron 43.1.0, one connection to a local listener,
  with the renderer's UDP policy set). What a prototype could send is what it
  holds, which its author already had. The agent's preview browser has its own
  no-route configuration (F14).
- Desktop does not close host-name lookups the page asks for. Electron has no
  per-session resolver rule and the app's other sessions need to resolve names,
  so a `dns-prefetch` link still makes the app's resolver look up a name the
  page chose. That carries little data and needs a nameserver the author
  controls. Closing it needs a boundary the Electron session does not give: a
  resolver rule for one session, or a prototype host that is a process of its
  own.
- The contained surface was measured on Electron 43.1.0 on macOS only. It was
  not measured in a packaged, signed app, and the pointer was not driven through
  a scaled surface on a real window (the scale was checked by reading pixels).
- A running frame in a remote browser is also not contained against a
  self-navigation to a page that runs its own script and makes its own
  requests (F7). What it can send is bounded by what the frame holds, which
  its author already had; the Run control says so.
- A tab hang in a remote browser that does not isolate sandboxed frames
  (F6): Playwright's old-headless Chromium shell hung the parent on a frame's
  infinite loop. Chrome for Testing kept the parent running, but kept the
  looping page's process for the next frame from the same host, so a
  prototype run again in that tab, even after a reload, did not load; a new
  tab did. The stopped message in a browser says to open a new tab.
- Before the person clicks into it, a running page can still take focus by
  script in some cases (observed on Electron 43 from a blur handler); it stays
  out of the tab order, and on desktop the reserved shortcut takes the
  keyboard back (F10).
- Chromium once stopped painting sandboxed frames that were `inert` or had
  `pointer-events: none` (0164). Every tier keeps frames hit-testable and
  covers a still frame instead.
- The secret filter cannot read markup. Shared and exported frames rely on
  the person's acknowledgement, not on scanning.
- An exported file is opened in the recipient's own browser. Its prototype
  cannot make a request or load another page (F11), but WebRTC is outside a
  page's policy and is not contained there, as in a remote browser (F3). What
  it could send is what the frame holds, which its author already had.
- A themed design is exported with token values the person's window hands
  over. They are written into a sandboxed frame's stylesheet after two checks
  (the contract's and the host's), only under names a frame receives, so a
  value cannot end its rule or name something to load, and the frame could
  load nothing if one did.
- Content inside a frame is the author's. A frame can look persuasive; F8
  keeps it from looking like Octant.
