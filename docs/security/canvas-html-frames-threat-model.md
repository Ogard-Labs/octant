# Canvas HTML frames threat model

- Date: 2026-10-10
- Threat model id: `canvas-html-frames-v1`
- Status: Accepted with
  [Canvas documents, designs, and prototypes](../architecture.md#canvas-documents-designs-and-prototypes).
  Static frames that run nothing ship today under
  [0164](../decisions/0164-canvas-designs-are-html-in-a-frame-that-runs-nothing.md),
  measured and themed static frames (F2) ship with Canvas schema version 16,
  asset-bearing static frames (F5) with version 17, and running frames with
  version 18, with F1, F3, F4, F6, F7, F8, F9, and F10 implemented and tested.
- Scope: agent-authored HTML, CSS, and script drawn in a Canvas `design`
  frame, in the sidebar, the thread, preview, authenticated snapshots, and
  HTML export

## What the frame can hold

A frame holds what its author wrote, plus assets the server resolved for it
under the thread's authority. The author is the agent working for this
person, which already has that content and its own tools. The boundary
therefore protects Octant and the person from the frame, not the frame's own
content from its author: a frame must gain nothing the agent did not already
have, must not reach anything beyond its own bytes, and must not cost the
person their app.

## Assets

- Octant renderer origin: cookies, storage, DOM, RPC, preload, host tokens
- Project files and artifacts beyond the assets a frame names
- Loopback services and the network from the person's machine
- Renderer responsiveness (hang, memory, GPU)
- The person's trust in what is Octant chrome and what is a frame
- Snapshot viewers and export recipients

## Explicit non-goals

- Typed catalog blocks, including `tabs`, `columns`, diagram styles, Gantt,
  and Mermaid import; they render first-party components and no markup
- Public or anonymous share links
- A frame that runs script with `allow-same-origin`; no tier admits it
- Protecting frame content from the agent that wrote it

## Frame tiers

| Tier                        | Document                                          | Sandbox                                                                       | Policy                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Static (0164)               | `srcdoc`                                          | empty                                                                         | Frame policy below, narrowing the inherited app policy                                                                                                                                                             |
| Static, measured and themed | `srcdoc`                                          | `allow-same-origin` only                                                      | Same; no script can run, so same origin grants the page nothing it can use                                                                                                                                         |
| Running                     | Served by the host route with a single-use ticket | `allow-scripts` only, in the parent and in the response's `sandbox` directive | `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; connect-src 'none'; frame-src 'none'; form-action 'none'; base-uri 'none'` |

The static frame policy is today's: `default-src 'none'; style-src
'unsafe-inline'; img-src data:; font-src data:; base-uri 'none';
form-action 'none'`. The app policy's `frame-src` admits `'self'` and the
loopback design-page path (the packaged `file://` and Vite renderers reach the
loopback host); the remote gateway's document policy narrows a remote
client's `frame-src` to that path on its own origin.

## Threats and mitigations

| ID  | Threat                                                          | Mitigation required before the tier ships                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | Running frame reads Octant state                                | Implemented. Opaque origin: the parent attribute is `allow-scripts` alone and the page is served with `sandbox allow-scripts`. No preload, host object, or credential reaches the page; the ticket is the only thing in its address. A renderer test draws every size and tier together and asserts no frame is ever given both `allow-scripts` and `allow-same-origin`. A browser smoke reads `self.origin` as `null`, and `document.cookie`, `localStorage`, and `parent.document` throw `SecurityError`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| F2  | Static frame with `allow-same-origin` acts as Octant            | No `allow-scripts`, so no script, event handler, or `javascript:` URL runs. The inherited app policy and the frame policy still apply. Markup refusals keep rejecting `meta`, `base`, embedded documents, form targets (`action`, `formaction`), and non-fragment links. Form controls stay allowed because CSS-only tabs need them; the sandbox grants no `allow-forms` and the frame policy sets `form-action 'none'`, so nothing submits.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| F3  | Frame sends data out                                            | Implemented. `connect-src 'none'`, `img-src data: blob:`, `frame-src 'none'`, and `form-action 'none'`; declared images are written in as `data:` images by the host. The browser smoke's fetch, XHR, WebSocket, image beacon, and form submit reach nothing. Desktop sets the renderer's WebRTC IP handling policy to `disable_non_proxied_udp`: an Electron 43 probe gathered a host candidate without it and none with it, and a second probe with a local listener saw its STUN datagrams stop. That policy closes UDP only. WebRTC over TCP is not contained on any client (see Residual risk), bounded by what the frame holds: its author's content and named assets.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| F4  | Ticket or session credential leaks to the frame                 | Implemented. The frame URL carries a single-use ticket (32 random bytes, held in memory, 10 seconds) issued by `POST /api/canvas/design-run` after the Canvas read check; it authorizes one version, design, and start frame, never a session token. The page route serves only a frame load, and every response, page or refusal, sends `Referrer-Policy: no-referrer` and `Cache-Control: no-store`. Route tests refuse a replayed, expired, guessed, or over-specified ticket, and a static design, another version, an unknown window, or another Project or mode.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| F5  | Asset reference reaches beyond authority                        | Implemented. The server resolves only asset ids the definition declares, under the Canvas version's mode, Project, and thread, on every read through the authorized Canvas read (no cache). A Chat Project reaches only images generated in its own threads, never a path. Work and Code files go through the Work confinement sequence: no traversal, no symlink out of the root, one identity-checked handle. Only sniffed PNG, JPEG, GIF, or WebP within 3 MiB per image and 5 MiB per design. The renderer inlines the bytes as `data:` images; the markup policy admits only literal references to declared ids, so a frame cannot request an asset at run time. Unknown, refused, oversize, or non-image ids draw a placeholder and a `design-asset-unavailable` preview warning; the definition and journal hold references, never bytes.                                                                                                                                                                                                                                                              |
| F6  | Running frame hangs or exhausts the renderer                    | Implemented. Electron 43 runs sandboxed frames out of process by default (probed for same-site, cross-site, and `file://` parents; the parent kept running through the frame's infinite loop), and desktop enables `IsolateSandboxedIframes` with per-document grouping explicitly, because the default per-site grouping put the next prototype into a looping page's process, where it never loaded. The bridge sends a heartbeat every second; a frame that misses 5 seconds of it (10 for the first) while the window is visible is removed and shown as stopped, with Run again, and so is a frame that posts more than 250 messages in a second to the renderer. The thread starts a running frame only on Run. A remote browser keeps hangs as a residual (below).                                                                                                                                                                                                                                                                                                                                     |
| F7  | Frame navigates the app, opens windows, or navigates itself out | Implemented. No `allow-top-navigation`, `allow-popups`, `allow-forms`, or `allow-modals`; the browser smoke's top navigation and `window.open` are refused. Static frames keep fragment-only links. Desktop cancels every navigation of a running frame except its first load of a ticketed page (Electron `will-frame-navigate`), knowing the frame by its frame tree node and by an address on the host, so a `history` rewrite does not hide it; an Electron probe cancelled `location = 'https://example.com/?x'`, a `meta` refresh, and a navigation after `pushState`. A remote browser cannot cancel it: there the navigated page can make any request a web page in that browser can, before and after it loads (the smoke's beacon saw it). Every client removes a frame on its second load, which limits how long such a page stays on screen, not what it sends. This remote exposure is accepted, bounded by what the frame holds; the Run control in a remote browser says the prototype is not network-contained there.                                                                         |
| F8  | Frame impersonates Octant chrome                                | Implemented. Frames sit inside a Canvas body with host chrome outside them; a running frame carries a visible Running label and its Stop control in host chrome. A frame never draws over the composer, approvals, or dialogs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| F9  | Bridge messages are forged or abused                            | Implemented. The parent accepts messages only whose `source` is that frame's window and whose origin is opaque, on the bridge channel, with a known type and bounded fields. Height is clamped to 48–12,000px; errors are cut to 280 characters and shown as text. Tests forge the source, the channel, and the field types. The bridge grants no tool call, journal write, file read, or navigation. Agent script can lie to the bridge; the worst outcome is a wrong size, a missed error, or a stop.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| F10 | Keyboard focus is trapped                                       | Implemented. Frame script can swallow Tab or keep refocusing itself, so ordinary focus order is not an escape. Desktop reserves Command-Escape (Control-Escape outside macOS), read through Electron `before-input-event` before any frame sees the key while a running frame has focus; the renderer moves focus to that frame's Stop and stops a page that takes focus back within a second. An Electron probe confirmed the frame never saw the key and that a page refocusing on blur takes focus straight back, which is why it is stopped. A running frame is out of the tab order until the person presses Run or clicks into it. A remote browser relies on the browser's own focus escape (F6 or the address bar) and the Stop control in host chrome; the user guide names both.                                                                                                                                                                                                                                                                                                                    |
| F11 | Shared or exported frame runs unsafely elsewhere                | Snapshots implemented. A snapshot carries frames only from share version 10, which a reader that never drew a shared frame refuses as a future version; the viewer draws a shared design with the live Canvas's own block, so the sandbox and page policy are the same, and a shared prototype's page is ticketed on a journaled share access and served by the page route. The sharer must acknowledge that markup is shared as written, and markup holding a credential in a recognisable shape is refused even then. Declared images do not leave. HTML export implemented: each frame is a sandboxed `srcdoc` page carrying the frame policy in the page, never with `allow-same-origin`; the document that draws frames carries `frame-src 'none'`, which refuses a frame that loads another page; and the export approval card names the markup it writes. The export frame smoke opens an exported hostile prototype from a file and asserts that it runs and that its fetch, XHR, WebSocket, image, form, popup, top navigation, and self-navigation reach nothing. Markdown export writes the title. |
| F12 | Older runtime draws a new tier unsafely                         | Each tier is a Canvas schema bump; an older runtime refuses the document as a future version.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| F13 | Remote client exceeds authority                                 | Frames, tickets, and assets use the same Canvas and Project authority as any block. A remote client gains no tool through a frame.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| F14 | The agent's preview runs a prototype on the host                | Implemented. `preview` runs a running design in the host's headless Chromium so its script errors can be read. The page is the one the page route serves, in a frame sandboxed to `allow-scripts` alone, inside a preview page that holds no server address or credential. Every request is intercepted and aborted except the preview's own built files and the design page the host built; the browser is started with no route out for what interception cannot see (a proxy that does not exist, loopback included, names that never resolve, and no WebRTC UDP outside that proxy). The preview browser smoke runs a hostile prototype and asserts that nothing arrives over HTTP, TCP, or UDP. What the host reads back from a frame (overflow, contrast, error text) is bounded and shape-checked as a claim, and a frame that hangs is left unmeasured; one preview runs per thread under a per-minute allowance.                                                                                                                                                                                     |

## Residual risk

- WebRTC is outside a page's content policy, and no client contains it fully
  (F3). On desktop the IP handling policy stops UDP, but a peer connection
  that names a TURN server over TCP still connects: on Electron 43.1.0 a
  sandboxed frame reached a local TCP listener with the policy set (one
  connection; four STUN datagrams without the policy, none with it).
  Containing it on desktop needs a boundary the renderer's own session does
  not give a frame, and is not built. The agent's preview browser is the one
  place it is closed, because that browser is started with no route out (F14).
- A running frame in a remote browser is also not contained against a
  self-navigation to a page that runs its own script and makes its own
  requests (F7). What it can send is bounded by what the frame holds, which
  its author already had; the Run control says so.
- A tab hang in a remote browser that does not isolate sandboxed frames
  (F6): Playwright's old-headless Chromium shell hung the parent on a frame's
  infinite loop. Chrome for Testing kept the parent running, but kept the
  looping page's process for the next frame from the same host, so a
  prototype run again in that tab, even after a reload, did not load; a new
  tab did. The stopped message in a browser says to open a new tab.
- Before the person clicks into it, a running page can still take focus by
  script in some cases (observed on Electron 43 from a blur handler); it stays
  out of the tab order, and on desktop the reserved shortcut takes the
  keyboard back (F10).
- Chromium once stopped painting sandboxed frames that were `inert` or had
  `pointer-events: none` (0164). Every tier keeps frames hit-testable and
  covers a still frame instead.
- The secret filter cannot read markup. Shared and exported frames rely on
  the person's acknowledgement, not on scanning.
- An exported file is opened in the recipient's own browser. Its prototype
  cannot make a request or load another page (F11), but WebRTC is outside a
  page's policy and is not contained there, as in a remote browser (F3). What
  it could send is what the frame holds, which its author already had.
- A themed design is exported with token values the person's window hands
  over. They are written into a sandboxed frame's stylesheet after two checks
  (the contract's and the host's), only under names a frame receives, so a
  value cannot end its rule or name something to load, and the frame could
  load nothing if one did.
- Content inside a frame is the author's. A frame can look persuasive; F8
  keeps it from looking like Octant.
