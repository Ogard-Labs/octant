# 0056. Image generation jobs, adapters, and artifact scope

**Status:** Accepted

## Context

0055 defines image profiles as `ProviderInstance` kinds. Generation itself is
a billed, non-idempotent provider call: restart must not re-invoke a job that
was in flight, safety refusals must stay refusals, and image bytes must not
enter the event journal. 0007's user-editable base URL would reopen SSRF;
0010 already stores preview targets as opaque refs, never bodies.

## Decision

- Image generation is a journaled job aggregate with lifecycle
  `queued | running | completed | failed | cancelled` — a subset of the
  AgentRun vocabulary, not a new one. Cancellation is an `AbortSignal` into
  the adapter fetch. A job still `running` after restart hydrates as `failed`
  with the reason `interrupted by restart` and is never re-invoked.
- Adapters are thin and plugin-shaped: one OpenAI Image API adapter and one
  Gemini native-image adapter behind a shared result type. Each kind has a
  fixed base URL. The API key is resolved per request from the existing
  credential broker. Request and response decoding reject URL forms; only
  base64/inline payloads become bytes. A job carries exactly one profile id.
  A safety refusal is terminal and is never retried on another provider.
- Generated bytes land in a `ManagedAttachmentStore` scope (staged →
  hash-verified finalize → recovery sweep, `maxBytes` bounded). The journal
  stores only `{ attachmentId, hash, size, mime }` plus generation evidence
  `{ profileInstanceId, modelId, promptHash, jobId, parentArtifactRef? }`.
- Completed jobs append `context.usage-reconciled@1` with
  `request_shape: "image-generation"` and image units in `attribution_json`.
  `USAGE_PROJECTION_SCHEMA_VERSION` does not change.
- Per-host concurrency is a small fixed cap so queued is a real state.
  Composer invocation, the agent tool, and thread preview are out of this
  record.

## Consequences

- Settings can hold an image profile and a key without implying that
  generation has run; jobs and artifacts appear only after an explicit later
  invocation path.
- Restart, cancel, and refusal fail closed without duplicate provider
  charges or partial files Octant can prevent.
- Follow-up adapters (polling URL results, extra vendors) reuse the job and
  attachment contracts rather than widening the journal.
