# Native UI assessment

Review date: 2026-10-26.

This is an assessment for follow-up work. The visual changes described here were
not implemented as part of the assessment. Use the current [design system](../DESIGN.md)
and [design index](design/README.md) when turning a recommendation into a change.

Screenshot paths below refer to artifacts kept locally during the original review.
The images are not included in the repository.

The main workspace already uses compact navigation, transcript reading space and restrained menus. Settings and the narrow sidebar remain the clearest places to make the app feel more like a desktop utility.

This assessment reviews the 25 saved production-browser captures in `/tmp/octant-ux`, including the menus, Code and Work threads, Inbox, Projects, Settings, search, light mode and narrow layouts. The contact sheet is `/tmp/octant-ux/contact-sheet.png`. I also inspected the General Settings, Providers, narrow Work thread and model-picker captures at full size. These are saved browser captures, not a fresh packaged Electron walkthrough.

| Priority | Finding and evidence                                                                                                                                                                                                                                                                                                                                                                                                                            | Recommended change                                                                                                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1        | Settings repeats page identity in a breadcrumb and a large icon/title header, followed by section-link pills. The controls begin well below that chrome. Visible in `17-settings-dark.png`, `18-settings-appearance-dark.png`, `19-settings-providers-dark.png` and `20-settings-data-dark.png`. `DESIGN.md` currently specifies the page shell and section pills, so this is an intentional design change rather than a broken implementation. | Use a compact preference-page heading and put section navigation in a restrained list or section chooser when needed. Keep the existing grouped setting rows: their labels, descriptions and controls are useful and already resemble native preferences. |
| 2        | Providers uses a two-column grid of individually rounded cards with prominent brand tiles, status lines, disclosure arrows and switches. The repeated boxes dominate the page in `19-settings-providers-dark.png`.                                                                                                                                                                                                                              | Use one aligned provider list with small icons, name/status and enable control on each row. Expand provider details within the list or an adjacent inspector. Preserve the separation between configured and other providers.                             |
| 3        | The narrow sidebar gives four large saturated status tiles more visual weight than the thread list. Visible in `24-narrow-thread-light.png` and `25-narrow-settings-light.png`. The compact rail in the wide dark captures is much calmer.                                                                                                                                                                                                      | In narrow layouts use compact navigation rows with counts, reserving strong colour for the selected destination or an urgent badge. Keep the counts accessible without the dashboard-sized blocks.                                                        |
| 4        | The character field remains visible behind prose and tables in the Work thread captures. GPU rendering solves draw cost, but visual motion and texture can still compete with reading.                                                                                                                                                                                                                                                          | Consider a still or more subdued reading-page treatment separately from animation speed. This is a visual preference; these screenshots do not establish a performance regression.                                                                        |

The model chooser in `04-model-picker-dark.png` has a useful compact list, search, checked selection and controls for the chosen model. Its rich content justifies a custom popover; replacing it wholesale with a simpler native menu would lose controls. A later desktop pass should verify keyboard focus, Escape, arrow navigation and dismissal.

The ordinary action/context menus, Inbox and Projects read as compact lists in the captures. There is no evidence here that their structure needs replacement. Browser menus do not prove the appearance or behavior of Electron's native macOS menus.

The four current performance PRs address separate measured or traced costs: idle readers, queue wakeups, eager Canvas loading and streaming parsing. This report makes no claim that those PRs implement the visual recommendations above.

Verified: saved capture review and current design rules. Still outstanding: a fresh packaged-app pass for native menus, keyboard behavior, startup and the GPU ground; the existing macOS test Space was unreachable during this round.
